# 04｜一步一步执行：从一句话到步骤序列

> 「PalatMind 是如何操作电脑的」系列第 4 篇。感知、理解、点击都有了，如何把它们串成一条完整的任务执行流。

[返回目录](../README.md#它是怎么操作电脑的)

## 先把目标拆成步骤

用户说的是目标，不是步骤。「打开酷狗播放周杰伦的《晴天》」拆开是一条明确的操作序列：

```
1. 启动酷狗音乐（已运行则前置到前台）
2. 定位搜索框，单击聚焦
3. 输入「周杰伦 晴天」
4. 触发搜索（回车或点搜索图标）
5. 等待结果列表出现
6. 在结果中定位《晴天》目标行
7. 双击行 / 点行内播放按钮
8. 确认播放栏出现「晴天」→ 完成
```

拆解要落到**每一步都可感知、可操作、可确认**：第 5 步"等待结果"不可省——界面加载需要时间，直接找目标必然找不到。

## 每一步的执行循环

每一步都跑同一个小循环：**感知 → 定位 → 操作 → 确认**。

```python
for step in plan:
    for attempt in retries:
        page     = perceive(screen())          # 看得见
        point    = locate(page, step.target)   # 看得懂
        if point is NOT_FOUND:
            handle_missing(step)               # 卡点处理，见下
            continue
        act(point, step.action)                # 点得准
        if confirm(step.expect):               # 即时确认
            break
    else:
        report_failure(step)                   # 重试耗尽，如实报告
        return
```

确认的锚点在规划时就想好（第 8 步的锚点是"播放栏出现晴天"），执行时只做判断——**每步确认通过才走下一步**，错误不会向后累积。

## 卡点处理：看不见、点不动、有弹窗

真实桌面不会配合你，三类卡点各有通用解法：

**1. 看不见目标（locate 返回 NOT_FOUND）**

- 先滚轮滚动一屏，重新感知再找——目标大概率在下面
- 还没有 → 检查是否有标签页/侧栏切换（如"歌单/电台"页签不对）
- 还没有 → 等待加载后重感知（第 5 步被跳过的后果在这里补上）

**2. 找到了但点不动**

- 元素是灰色禁用态 → 等待其可用（如按钮在加载完成前禁用）
- 点击无反馈 → 换交互方式：单击改双击、坐标点击改键盘回车、点行改点行内按钮

**3. 意外弹窗**

更新提示、广告弹层、权限弹窗随时可能盖住目标。每次感知时顺带检测"预期外的顶层弹窗"：可识别的弹窗直接关闭/取消后继续主流程；识别不了的停下来问用户——**绝不盲点未知弹窗上的按钮**。

## 卡住的底线：换路与止损

- 同一步换方式重试（几种交互方式轮一遍），仍失败 → 进入重规划（这条路不通，换一条：比如找不到播放按钮，就改用双击行）
- 止损原则：**预定的最终确认锚点没达成，任务就不算成功**——宁可如实报告"没完成"，绝不把"点过了"说成"完成了"

## 执行轨迹本身是资产

这条步骤序列连同每步的定位结果、确认锚点，就是一份完整的**执行轨迹**。任务成功后，它值得被留下来——下一篇讲如何把成功轨迹沉淀成可复放的自动化脚本，让同类任务从分钟级降到秒级：[05 成功案例变脚本](05-success-to-script.md)。
