# 02｜找对元素：UIA 控件树与视觉识别的双通道定位

> 「让 GUI 自动化更精准」系列第 2 篇。窗口找对了，下一个问题是：按钮在哪？

[返回目录](../README.md#技术专栏让-gui-自动化更精准)

## 为什么"有的应用好找，有的应用找不到"

打开 inspect 之类的工具看两个应用，你会发现一个应用控件树枝繁叶茂（每个按钮都有名字），另一个应用整棵树只有一个空壳。这不是工具的问题，而是**应用用了两套完全不同的 UI 技术**：

| 类型 | 典型代表 | 控件树（UIA）表现 |
|------|---------|------------------|
| 标准控件体系 | Win32、WPF、Qt、UWP | 完整：类型、名称、状态、模式齐全 |
| 自绘 UI | 部分播放器、游戏、自研框架 | 空壳：只有窗口本身，内部全是"一张图" |

定位策略因此必须**双通道**：控件树优先，视觉识别兜底。

## 通道 A：控件树（UIA）——又快又准的首次尝试

UIA（UI Automation）能拿到控件类型、名称、AutomationId、启用/禁用状态，还能通过 Pattern 直接调用行为（如 `InvokePattern` 点按钮、`ValuePattern` 读写文本）。

**优势**：

- 精确命中，不受主题、皮肤、分辨率影响
- 便宜：毫秒级、零截图开销
- 可验证：能读到 `IsEnabled` 等状态，天然支持后续验证

**注意事项**：

- 匹配条件别太松：只按 Name 找"确定"，可能命中隐藏的多个同名控件；优先 `AutomationId`，其次 Name + ControlType 组合，最后限定搜索范围（目标窗口子树内）
- 中文界面的 Name 就是中文，注意大小写与全半角
- 树结构是懒加载的，深搜大应用时控制超时

## 通道 B：视觉识别——自绘 UI 的兜底

控件树是空壳时，只剩一条路：截图 + 视觉定位。按成本从低到高有三档：

1. **模板匹配**：适合图标、固定样式按钮。要处理缩放（多尺度匹配）和深色/浅色主题两套模板
2. **OCR**：适合找文字。中文小字号识别率会掉，且拿到的是像素坐标
3. **视觉语言模型**：给截图 + 自然语言目标（"找到搜索框"），返回坐标。泛化性最强，成本最高，适合作为最后兜底

## 双通道融合：让兜底结果"升级"回元素级

关键设计：**通道 B 找到的坐标，先尝试对齐回通道 A 的元素**。

```python
def locate(target_desc, hwnd):
    # 通道 A：控件树精确查找
    el = uia_find(hwnd, target_desc)
    if el:
        return ElementTarget(el)          # 有状态、可 Pattern 调用

    # 通道 B：视觉兜底，得到像素坐标
    pt = vision_locate(screenshot(hwnd), target_desc)

    # 对齐：坐标若落在树中某元素的 Bounds 内，升级为元素级操作
    host = uia_element_from_point(hwnd, pt)
    if host and host.control_type in CLICKABLE:
        return ElementTarget(host)        # 坐标 + 元素双重确认

    return PixelTarget(pt)                # 纯坐标，操作后必须强验证
```

升级的价值：元素级操作可以被 `InvokePattern` 直接触发（不依赖坐标，永不偏移），且状态可读，为第 4 篇的"结果级验证"提供支点。纯坐标操作是最后手段，必须搭配强验证。

## 实战细节

- **别读屏拿文本**：需要文本内容时优先 UIA 的 `ValuePattern` / `TextPattern`，OCR 只做兜底——OCR 对形近字（0/O、1/l）的错误会顺着流程传播
- **动态内容**：列表、推荐位是滚动的，先滚动到目标可见再定位，不要假设首屏包含一切
- **定位结果要带时效**：窗口尺寸变化、页面切换后旧坐标全部作废。定位结果绑定"窗口状态指纹"（尺寸 + 关键锚点），指纹变了就重新定位

## 小结

| 场景 | 首选 | 兜底 |
|------|------|------|
| 标准控件应用 | UIA 属性匹配 + Pattern 调用 | —— |
| 自绘 UI | 视觉定位 → 对齐回元素 | 纯坐标 + 强验证 |
| 需要读文本 | UIA Text/Value 模式 | OCR |
