# 04｜记忆系统：分层记忆与按需检索

> 「PalatMind 技术分享」系列第 4 篇。只谈理念，不含源码。

[返回目录](../README.md)

## 一个反直觉的设计决策

很多 AI 应用的做法是：把所有历史对话、所有记忆、所有工具结果压缩成一份超长上下文，每次全部塞给模型。实测后发现这条路走不通：

- **Token 成本爆炸**：每轮注入十几万字符，成本与延迟不可接受
- **信息丢失**：压缩必然丢细节，而细节恰恰是"上次你说要哪个版本"这类关键信息
- **注意力稀释**：无关信息越多，模型对关键信息的召回越差

PalatMind 的选择是：**模型不被动接收，而是主动检索**。

## 分层记忆

| 层 | 内容 | 注入方式 |
|----|------|---------|
| L0 身份层 | 核心身份、系统偏好、刚性约束 | 始终常驻（极小预算） |
| L1 关键层 | 近期重要决策、用户核心偏好 | 始终常驻（小预算） |
| L2 按需层 | 当前任务相关记忆 | 模型通过工具拉取 |
| L3 深度层 | 全库语义搜索 | 模型通过工具拉取 |

常驻的只有 L0/L1（合计千 token 级），其余全靠检索工具按需获取。

## 两种检索路径

1. **结构化过滤**：明确知道信息属于哪一类（空间坐标）时，按元数据过滤——精确度接近 100%，适合"上次那个项目的配置"
2. **语义搜索**：不知道在哪时，向量相似度搜索——适合"以前有没有遇到过类似问题"

高分结果还可以进一步做**知识图谱扩展**，把孤立事实变成关联网络（某项目的作者 → 作者的其他作品 → 相关项目）。

## 何时强制检索

按需检索最大的风险是模型"不知道何时去查"。解法是在系统提示层按输入模式注入强制指令：

| 触发模式 | 强制指令 |
|---------|---------|
| 选择题 / 多选项 | 逐一检索每个选项的证据再作答 |
| 用户问"上次 / 之前 / 历史" | 先查历史记忆再回答 |
| 事实性断言 | 先检索支持或矛盾的证据 |
| 跨会话引用 | 先取历史上下文 |

## 检索结果的无损治理

检索结果注入前，只做**不丢信息**的三类处理：

- **去重**：重复内容只保留一份——信息集不变
- **相关度过滤**：按与当前查询的真实相关度排序与过滤，不按存储顺序透传
- **条数收敛**：常驻注入有条数上限，但全量信息仍可随时通过工具拉取

**禁止截断**：截断是丢信息的行为，短信息在截断中丢失率最高。防膨胀靠无损机制，而不是砍信息。

## 记忆的可靠性

- **持久化后端 + 写入审计**：重启不丢，操作可追溯
- **结构化召回必须精确**：明确知道坐标时，不允许漏召回
- **反思闭环**：任务失败的记忆被记录，供后续任务参考，形成"执行 → 反思 → 改进 → 再执行"

## 小结

记忆系统的好坏，不取决于存了多少，而取决于**该想起的时候能否想起、不该打扰时是否安静**。分层常驻 + 主动检索 + 无损治理，是我们找到的平衡点。
