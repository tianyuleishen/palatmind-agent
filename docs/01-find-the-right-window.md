# 01｜找对窗口：影子窗口、DPI 与多显示器三大陷阱

> 「让 GUI 自动化更精准」系列第 1 篇。一切精准操作的前提，是你操作的窗口真的是你想要的那个。

[返回目录](../README.md#技术专栏让-gui-自动化更精准)

## 三个典型"灵异现象"

做桌面自动化的朋友大概率见过其中之一：

1. **点了但没反应**：脚本返回点击成功，界面毫无动静。事后排查发现：点击坐标落在一个不可见的伴生窗口上。
2. **截图和用户看到的不一样**：截出来是灰的、空的、或者干脆是另一屏的内容。
3. **换台机器全点偏**：在自己 100% 缩放的显示器上分毫不差，到了同事 150% 缩放的笔记本上系统性偏移，越点越歪。

这三个现象的根因分别是：影子窗口、DPI 缩放、多显示器。下面逐个拆解。

## 陷阱一：影子（装饰）窗口

很多自绘 UI 框架（播放器、聊天工具、游戏启动器常见）除了你看到的那个渲染窗口，还会创建一个**不可见的伴生窗口**——用于接收系统消息、实现阴影边框或动画特效。

问题在于：`EnumWindows` / `FindWindow` 拿到的第一个顶层窗口，往往就是这个影子窗口，而不是渲染窗口。在影子窗口上做任何事——设为前台、找控件、截图、`WindowFromPoint` 校验——都会静默失败或拿到错误结果。

**识别影子窗口的通用特征：**

- 窗口类名属于已知框架特征（如 `LwaShadowWnd` 一类）
- 窗口尺寸为零、或可见区域（region）为零
- 无标题、无控件子树、`IsWindowVisible` 为真但视觉上不可见

**通用解法（伪代码）：**

```python
def pick_render_window(pid):
    candidates = []
    for hwnd in enum_top_level_windows():
        if get_pid(hwnd) != pid:        continue
        if not is_window_visible(hwnd): continue
        rect = get_window_rect(hwnd)
        if rect.area <= 0:              continue
        candidates.append((hwnd, rect.area))
    # 面积降序：渲染窗口几乎总是同级窗口中最大的那个
    return sorted(candidates, key=lambda x: -x[1])[0][0]
```

要点：**不要相信枚举顺序，用"可见 + 有面积 + 按面积排序"重选渲染窗口**。这一个动作能消灭一大类"点了没反应"。

## 陷阱二：DPI 缩放

Windows 的 Per-Monitor V2 时代，不同显示器可以有不同的缩放比例（100% / 125% / 150%…）。坐标相关的新手坑全在这里：

- 你的进程若没有声明 DPI aware，系统会对你的坐标做**虚拟化换算**，`GetWindowRect` 返回的是"假坐标"——看起来有值，点击必偏
- 用一个进程的坐标去操作另一个 DPI 感知状态不同的进程，物理像素和逻辑像素混用，偏移量随缩放比例放大

**解法清单：**

1. 进程清单（manifest）声明 **Per-Monitor V2 DPI aware**，这是一切的前提
2. 全链路统一用**物理像素**计算：获取窗口矩形、元素矩形、屏幕坐标都用同一坐标系
3. 涉及缩放/移窗到另一屏时，用 `MonitorFromWindow` + `GetDpiForMonitor` 显式换算，不要凭"比例"心算

验证方法很简单：把一台显示器设 150% 缩放，写个脚本点击"开始菜单"按钮。点 100 次全部命中，你的坐标系统才是对的。

## 陷阱三：多显示器

- **负坐标**：位于主屏左侧的副屏，x 坐标是负数。大量代码里 `if (x >= 0 && y >= 0)` 的"有效性检查"会把它误判为无效——然后用 0,0 替代，点击飞到主屏左上角
- **显示器枚举**：用 `EnumDisplayMonitors` 动态获取，不要硬编码"只有一块主屏"
- **特殊会话**：锁屏、睡眠恢复、RDP 远程会话中，枚举结果可能为空或突变，自动化流程要能探测并等待，而不是拿着空列表继续跑

## 上线前检查清单

- [ ] 按 PID 枚举后重选了渲染窗口（可见 + 有面积 + 面积排序），而不是用枚举第一个
- [ ] 进程声明了 Per-Monitor V2，全链路物理像素
- [ ] 150% 缩放 + 双显示器（含负坐标副屏）实测点击无偏移
- [ ] `WindowFromPoint` 校验：点击目标点实际命中的窗口 == 目标窗口
