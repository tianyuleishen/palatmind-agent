# 03｜点得准：鼠标的正确使用方式

> 「PalatMind 是如何操作电脑的」系列第 3 篇。定位给了精确坐标，最后一步由鼠标执行——而鼠标远不止"单击"一种用法。

[返回目录](../README.md#它是怎么操作电脑的)

## 鼠标操作全集

人对鼠标的全部用法，Agent 都要用上，用对场景：

| 操作 | 典型场景 |
|------|---------|
| 左键单击 | 点击按钮、聚焦输入框、选中列表行 |
| 双击 | 打开列表行（双击播放/打开文件）、打开桌面图标 |
| 右键 | 呼出上下文菜单（复制、属性、更多操作） |
| 按住拖拽 | 滑块调节、选中文本、拖动排序、移动窗口 |
| 滚轮 | 长列表滚动、页面翻动 |
| 悬停 | 展开悬浮菜单、查看提示 |

**场景用错操作是常见失误**：单击列表行只是"选中"，双击才是"打开"；对滑块用单击永远拖不到目标值。执行前先确认该用什么操作。

## 点击前的三件准备

1. **窗口在前台**：`SetForegroundWindow` 后必须验证真的前台化了，失败则重试——向后台窗口点击等于空点
2. **目标在可视区**：列表第 50 行不在屏幕上，先滚轮滚到位，**滚动后重新感知定位**（页面变了，旧坐标全部作废）
3. **目标可点**：理解层判定非禁用态（见[上篇](02-understand-the-page.md)）

## 点击位置的精度细节

- 默认点**元素框中心**：中心是热区最稳的位置，离边缘越近误触风险越大
- 文字入口点**文本框中心**，不要点整行右端的空白
- 行尾小按钮（如每行的播放▶）点按钮自身中心，不点行中心——否则变成"选中行"而不是"播放"

## 双击与拖拽的参数细节

**双击**：两次点击间隔要小于系统双击阈值（`DoubleClickTime`，默认 500ms），且两次点击位置几乎不动（系统有像素容差）。拆成两次独立的慢点击 = 两次单击，结果完全不同。

**拖拽**：不是"瞬间从 A 跳到 B"，要分步执行：

```python
def drag(from_pt, to_pt):
    move(from_pt)
    press()
    for pt in interpolate(from_pt, to_pt, steps=15):   # 分多段移动
        move(pt); sleep(0.02)
    release()
    # 拖完重新感知：滑块位置/选区是否到位
```

分段移动对滑块、文本选区这类连续量操作尤其重要——瞬移式拖拽在一些自绘控件里会丢事件。

## 点击后的即时确认

点了不算完，**看到反馈才算点中了**：

| 操作 | 预期反馈 |
|------|---------|
| 点输入框 | 出现闪烁光标 |
| 点按钮 | 界面切换 / 新元素出现 / 按钮态变化 |
| 双击列表行 | 打开播放/详情 |
| 右键 | 菜单弹出 |
| 拖拽滑块 | 滑块位置变化 |

点击后短窗轮询预期反馈：出现 → 进入下一步；没出现 → 换方式重试（如单击改双击、坐标改键盘），而不是原样再点一遍。每步小确认，错误就不会滚到后面的步骤里。

## 一个绕不开的底层前提

以上一切坐标运算都要在**物理像素**域进行：进程声明 Per-Monitor V2 DPI 感知，跨缩放显示器（100%/150% 混用）与多屏（含负坐标副屏）下点击才不偏。这是"自己机器准、别人机器偏"的头号根因，工程上必须最先做对。
