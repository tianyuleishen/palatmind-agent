# 01｜桌面 Agent 架构：感知—规划—执行—验证的闭环

> 这是「PalatMind 技术分享」系列的第 1 篇。本系列只讨论理念与方法论，不涉及源码。

[返回目录](../README.md)

## 为什么桌面 Agent 难做

构建"能操作电脑"的智能体，最难的不是让模型生成一段操作序列，而是让整个系统在真实、混乱的桌面环境里稳定闭环。

- **环境不可控**：每个用户的桌面都不同——分辨率、缩放、主题、多显示器、应用版本
- **应用不标准**：相当一部分应用使用自绘 UI，不遵循系统控件规范，无障碍树拿不到任何信息
- **状态不可见**：同一个按钮，可能因加载、禁用、弹窗遮挡而处于完全不同的状态
- **后果不可逆**：误点删除、误发消息的代价，远高于聊天场景答错一句话

这就是为什么简单的"截图 → 让模型输出坐标 → 点击"管道在演示里惊艳，在真实使用里脆弱。

## 感知：先"看见"，才能操作

桌面 Agent 的感知层需要同时利用三类互补的信息源：

1. **系统控件树**：操作系统提供的 UI 自动化接口（如 UIA），能拿到控件类型、名称、状态，精确且便宜，适合标准应用
2. **屏幕视觉理解**：截图 + 视觉模型，能理解自绘 UI、图片按钮、复杂布局，是无障碍树失效时的兜底
3. **窗口与进程元数据**：窗口标题、类名、进程信息、前台状态，用于快速判断"现在哪个应用在面前、长什么样"

工程上的几个关键点：

- **多显示器与 DPI 适配**：坐标必须在统一的逻辑坐标系里计算，否则缩放不一致时点击会系统性偏移
- **装饰窗口识别**：很多应用存在不可见的"影子窗口"（shadow/decoration window），视觉上看到的窗口和系统枚举到的第一个窗口未必是同一个，截图前要重选到真正的渲染窗口
- **感知结果要结构化**：感知层输出的不是一段自然语言描述，而是可被后续步骤精确引用的元素定位

## 规划：先列步骤，再动手

PalatMind 坚持两条规划原则：

**第一，理解交给模型，不交给关键词。**"播放周杰伦的晴天"不是靠正则匹配出"播放"两个字来决定走什么路径，而是让 LLM 完整理解任务意图后自主决策。关键词触发在实测中反复出现误触发（比如把搜索任务误判成播放任务），是桌面 Agent 最常见的"看起来能跑但总是做错"的根源。

**第二，路径优先级：命令 > API > GUI。** 能用一条命令完成的任务（查磁盘空间、判断进程是否运行），绝不打开图形界面去点。GUI 是最后手段，不是默认手段。

对必须走 GUI 的任务（如没有命令行入口的播放器），规划阶段要求输出显式计划：

- 第一步做什么
- 第二步做什么
- 最终结果用什么信号确认

禁止"边探索边执行"——那是人类新手的操作方式，不是可靠系统的操作方式。

## 执行：通用原语，而非场景脚本

执行层的全部价值在于"通用"：

- 点击、输入、滚动、拖拽、快捷键是通用原语
- 窗口枚举、前台切换、文本提取是通用能力
- 判断某段逻辑是否合理有一个简单标准：**换个应用还能用吗？** 能 → 通用能力，进工具层；不能 → 场景脚本，禁止写进代码

场景化的"怎么做"（比如播放类任务的推荐步骤）应该沉淀在提示词与技能描述里，让模型自主决策；工具层只负责提供可靠的"会做"。

另外，每个工具都应声明**幂等性**：重复执行是否安全？失败后能否重试？发邮件、写文件这类非幂等操作必须配合去重机制，否则一次网络重试就可能造成重复发送。

## 验证：防"假成功"

这是桌面 Agent 与聊天机器人最大的分水岭。没有验证闸门的 Agent 会理直气壮地宣布失败的任务"已完成"——按了两下媒体键就说"歌曲播放中"，实际前台应用根本没变。

PalatMind 的验证设计：

- **结果级验证**：以任务目标为导向提取验证条件（如目标歌名应出现在窗口标题或播放栏中），而不是以"动作已执行"为准
- **多通道验证**：窗口标题、控件元素、剪贴板内容、视觉确认可组合使用
- **失败必须回流**：验证不通过时，将差异注入上下文让模型修正重试；重试耗尽后如实报告失败——绝不静默降级为"应用已打开"这种假通过
- **视觉确认基于有效截图**：截图无效（如截到装饰窗口）时不得放行

## 闭环：感知 → 规划 → 执行 → 验证 → 再感知

单次循环只是基础，真正的价值在闭环：验证失败的信息回到感知层，重新观察环境，修正计划，再次执行。这个循环的收敛速度，直接决定了任务成功率与耗时。

## 小结

| 阶段 | 关键原则 |
|------|----------|
| 感知 | 三源互补（控件树/视觉/元数据），DPI 与装饰窗口是两大坑 |
| 规划 | 模型理解意图，禁止关键词触发；命令 > API > GUI；先规划后执行 |
| 执行 | 通用原语，场景逻辑不进代码；工具声明幂等性 |
| 验证 | 结果级、多通道、失败回流、禁假通过 |
